# 加急入库预约

入口：试剂管理 → 加急入库。保留一个页面，项目组提交预约、样品管理员处理，不设审批、不直接改变库存。

## 临床方案 / BAS（项目号）数据源（2026-11-03）

加急入库的临床方案、BAS（即项目号）改为使用老样本系统同步数据（`reagent_clinical` / `reagent_item`），支持模糊搜索：

- **临床方案**：单选，来源 `reagent_clinical`，下拉只显示临床方案编号，按编号模糊搜索；仍允许直接输入新编号。
- **BAS 号（项目号）**：多选，来源 `reagent_item.base_id`（如 `22BAS0055`），按已选临床方案过滤；允许直接输入带后缀的 BAS（如 `22BAS0055-Blind`），保存时仍以「、」拼接进 `bas_nos`。**不再单独设“项目号”字段，BAS 号就是项目号。**
- **领用台账（PC + 手机端）**：列表搜索框改为 BAS 模糊提示（仍可按输入值查询）；新增/修改表单的 BAS 号改为同源模糊提示/下拉，允许输入特殊 BAS。
- 新增字段：仅 `sample_urgent.clinical_id`；执行 `sql/postgresql/增量/2026-11-04-02-reagent.sql`。
- 下拉接口：`GET /reagent/basic-data/clinical-options`、`GET /reagent/basic-data/item-options`；已有加急/领用 query 权限即可访问。

## 项目组登记

- 临床方案编号必填，支持在一条预约中填写多个方案，同方案可分批次重复预约。
- 检测项使用可搜索、多选、允许自定义的下拉。历史同义写法合并为所有检测管、所有样品、PK/ADA/PD检测管等常用选项；物流单号、到样说明放备注。
- 新项目必须填写BAS号，允许多个并保留Blind等后缀。
- 预约入库时间精确到时分。预约人搜名字选择，可多人，默认当前用户，允许代预约。
- 本次通知的样品管理员可选部门（含启用子部门）、人员或两者一起选择；人员去重，均须具备查看、处理权限。前端在当前会话内记住该用户上次提交的通知范围，仍需每次确认。
- 备注可选。新表单不再要求项目联系人、加急原因、预计到样、计划检测或物流单号；旧值保留在详情的历史字段中。
- 预约人姓名由后端根据账号生成快照，不能通过客户端文字冒名。选择人员不授予任何权限。

## 业务权限和处理

提交人是实际提交账号，不随预约人变化。提交人及任一预约人，具备相应修改权限时，可修改、取消未结束预约；实际操作人记录在处理记录中。修改和取消需填原因。项目相关人员和样品组可补充说明。

我的预约按预约人筛选；未确认预约人的旧记录暂按原提交人归属。另有我提交的、待我处理、今日到期、逾期筛选。关键词覆盖临床方案、BAS、检测项、备注及历史物流单号。

样品组可直接处理或先接手；接手后由当前处理人更新进度。部分入库须说明已入库和剩余范围；全部入库须无剩余范围、无未解决异常，并填写实际入库时间。已结束预约不能直接修改状态，可补充说明。版本号及行锁防止并发覆盖。

## 钉钉通知

- 新增预约发给本次选定的管理员部门/人员；修改、取消及预约方补充说明优先通知当前处理人，未接手时通知选定管理员。
- 接手、进度、异常、完成及样品组补充说明通知全部预约人。提交人不因代录入额外接收；若其也是预约人则正常接收。
- 收件人去重并排除本次操作人。未绑定钉钉的指定人员仍登记通知，由通用发送服务记录明确失败；不静默忽略其他接收人。
- 新增及变更时提前登记未来临期通知，发送时间为预约时间前120分钟。新增时已进入临期窗口，仅登记即时通知；启动补齐也不会再生成同一条临期提醒。完成、取消或改期会取消旧待发临期通知。
- 模板编码sample_urgent_notice，使用Markdown。仅对没有选择通知范围的旧记录沿用模板默认管理员；未确认预约人的旧记录暂通知原提交人。
- 通知和业务在同一事务提交。现有Quartz任务dingTalkNotificationSendJob按计划发送时间读取队列，默认每30秒一次。通知管理只负责查询、取消及受控重发，详见dingtalk-notification-queue.md。

## 通用接收范围解析

本业务不再查询部门成员或拆分每人的消息。保存时通过通用人员解析API校验所选范围，通知时直接把部门、人员、排除的操作人、内容和计划时间交给通用队列。业务仅保留样品管理员/预约人资格判断。模板默认接收范围也复用同一通用解析服务，系统通用模块不再硬编码加急入库权限。此次内部职责调整不新增SQL、页面或定时任务，沿用已执行的预约改造迁移；更新后端并重启生效。

## 删除与排序

列表支持逻辑删除，复用修改预约权限，仅提交人或预约人可操作，后端校验归属和版本。保留原始数据及处理记录，同时取消该预约待发送通知。无需新增数据库字段或权限菜单。列表按未结束的逾期预约优先，两组各自按登记编号倒序，全局分页排序由后端执行。

## 消息模板字段（2026-11-03）

旧变量不保留。更新前停止后端，执行sql/postgresql/增量/2026-11-04-02-reagent.sql，将现有模板占位符和可继续发送通知的参数同步到新名称，再更新前后端并启动。SQL保留模板固定文字、接收配置、计划时间和状态，不改已受理记录或实际发送日志。迁移不会从当前业务记录猜测旧快照中缺失的数据。

模板编辑器会从本业务的字段提供器获取字段说明和示例，通用模板模块不硬编码加急字段。支持点击复制占位符，模板预览和测试发送显示中文字段名。

- action：本次事项；registrationNo：登记编号；clinicalProtocolNo：临床方案编号；testItems：检测项；basNos：BAS号。
- reservationTime：预约入库时间；appointmentNames：预约人；submitterName：实际提交人；noticeRecipients：本次选定通知范围的姓名快照；handlerName：处理人；status：入库状态。
- remark：预约备注；completedScope：已完成范围；remainingScope：剩余范围；exceptionTypeName：异常类型中文名；exceptionNote：异常说明；actualInboundTime：实际入库时间。
- changeReason：修改原因。固定提醒文字由模板编辑。接口不再提供含义混杂的content汇总字段。
- 接口不提供detailUrl。跳转地址由模板作者自行填写固定地址，如[查看详情](https://example.com/reagent/sample-urgent?id={registrationNo})。

不适用或缺失的字段统一以“—”表示。旧的urgentNo、projectNo、sampleScope、deadline、contacts、requester、handler、content及detailUrl不再作为模板参数输出，不能再用于新模板。历史快照原值仍可在系统处理记录/已发送日志查看。

已对接业务的模板字段以接口声明为准。模板编辑器不将未声明字段列为可用变量，引用未声明变量时禁止保存/预览/测试发送；后端保存、预览及实际发送也统一校验，不能通过手动请求绕过。
