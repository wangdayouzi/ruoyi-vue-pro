# PMS 知识库编号、属性与有效性审阅实施记录

## 已确认的业务口径

- 知识库用于文件和文档的查阅；培训、考核不在本次范围。
- 当前按单组织使用，不为新功能增加租户配置界面。
- 新库刚开始使用，不做存量文档编号迁移。
- 自定义属性只保存当前值；文件历史版本不复制属性快照。审阅记录独立留痕。
- 编号领取后不回收，允许空号；PMS 在创建保存时由后端取号，取消表单不取号。
- 每个新建文档/文件都必须取得业务编号；当前位置未配置生效的知识库或一级文件夹规则时，后端拒绝创建并回滚。
- 新的通用编号能力独立于 MES；现有 MES 编码规则与仓库使用保持可用。
- 编号规则、审阅规则由知识库提供默认值，一级主文件夹可覆盖，子文件夹继承主文件夹。
- 属性按知识库配置，目录暂不覆盖。

## 现状与边界

- MES 已有编码规则、分段、Redis 流水计数和生成记录，但模块边界和发号时机不适合直接作为 PMS 的通用服务。
- PMS 知识库已有文件夹、权限继承、文件/富文本、系统历史版本、搜索、回收站；文档尚无业务编号、动态属性和有效性审阅。
- 工作区现有大量未提交改动，实施期间不得清理、覆盖或回退这些改动。

## 实施步骤

1. 核对相关表结构、接口和前端入口，锁定新增字段及 API 契约。
2. 新增独立通用编号规则、计数和发号记录；实现固定前缀 + 补零流水、可选年度重置；不复用 MES 数据表。
3. 知识库及一级主文件夹绑定编号规则；新建文档/上传文件在服务端原子取号并保存唯一业务编号。
4. 新增知识库属性定义及文档当前属性值；接入创建、编辑和详情。
5. 新增审阅规则和独立审阅记录；接入临期/逾期待审列表和有效性展示。
6. 编写 MySQL/PostgreSQL 增量脚本、权限菜单，并做编译、类型检查及必要的业务测试。

## 关键约束

- 完整编号必须有数据库唯一约束；规则停用或变更不得影响已发编号。
- 目录移动不改已发编号；审阅逾期仅表示待核查，不自动判失效。
- 回收站不是失效文件档案；作废/替代状态与删除状态分离。
- 若某一步发现现有实现或工作区状态阻碍安全集成，在本文记录具体阻碍及已验证范围。

- 审阅周期从文档创建日或最近一次“有效”结论日期计算；“待确认”不重置周期。配置的提前天数决定何时进入待审清单，逾期不自动改为作废或失效。
