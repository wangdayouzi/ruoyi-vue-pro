# 钉钉消息模板管理与发布

## 当前能力

入口为“系统管理 → 钉钉消息 → 消息模板 / 发送记录”。基于已联通的企业内部应用机器人发送给员工，沿用通用接入的凭证与 token 缓存。robotCode 默认使用 Client ID，当前企业机器人的 code 与 Client ID 一致；独立机器人可用 DINGTALK_ROBOT_CODE 覆盖。

支持文本、Markdown、链接、图片、单按钮卡片、双按钮卡片、三按钮卡片。编辑器按类型显示字段，提供示例填充、参数自动识别、参数预览值、服务端预览校验、复制模板、启停及测试发送。示例中的 example.com 地址需替换为真实业务地址。卡片按钮当前只负责链接跳转，不执行审批或表单回调。互动卡片、文件上传、群发送及工作通知渠道尚未接入。

模板语法是 {taskName}，变量名以字母开头，只使用字母、数字和下划线。标题、正文、链接与按钮文字都会识别参数。每个变量均须传入非空字符串。服务端逐字段替换再序列化 JSON，避免引号、反斜杠等破坏消息体；不会递归解释变量值中的占位符。URL 必须预先写明 HTTP、HTTPS 或 dingtalk 协议，动态 URL 参数由调用方做好 URL 编码。

预览为布局示意，最终样式以钉钉客户端为准。Markdown 预览禁用原始 HTML，并使用 DOMPurify；预览链接不可点击。图片/链接类型的图片地址须钉钉客户端可以访问。

## 发布顺序

1. 在维护窗口执行 sql/postgresql/增量/2026-11-04-01-dingtalk.sql。脚本可重复执行，创建两张表、两个业务序列、菜单和按钮权限。脚本会锁定菜单表并校正菜单序列，期间不要并发维护菜单。
2. 发布新的后端 JAR 和 PC 前端 dist 目录内容，重启后端。
3. 超级管理员重新登录或刷新权限。其他角色需要授权目录、页面及对应按钮；租户套餐启用了菜单限制时，也需要加入新菜单。不要清空整个 Redis；必要时使用现有权限刷新机制或重启应用。
4. 在钉钉后台确认机器人已启用、已发布，开通“企业内机器人发送消息权限”，应用可见范围覆盖测试员工。员工需要属于同一企业，系统用户可通过通讯录同步的 dingTalkUserId 或已有钉钉登录绑定识别；只有登录绑定时，发送前会调用根据 UnionID 获取企业 userId 的接口，需保证应用可查询该员工。Stream 联通只证明接收通道可用，不证明机器人主动发送权限可用。
5. 新建一个文本模板，选择自己作为测试员工，填写参数后点击“发送测试”。检查钉钉实际收件与发送记录，再逐项验收其他类型。

正式数据库本次不自动执行 SQL，真实员工消息本次不自动发送。

## 其他模块调用

模板可配置默认接收部门及指定人员。部门支持树形多选和“包含子部门”（默认开启）；指定人员最多20人，部门展开后的成员不受此限制。人员和部门成员在业务发送时合并去重，部门调动、停用及钉钉绑定变化按发送时数据生效。只保留已启用、已关联钉钉的成员，加急入库还要求查看及处理权限。部门不存在或停用时不可保存；发送时移除已失效部门。

`DingTalkMessageSendApi.getDefaultUserIds(code)` 返回当前租户模板解析后的默认人员；`send` 的显式 userIds 保持原语义，不会自动合并默认范围或额外抄送。加急入库逐人调用发送接口，每次不超过接口20人的限制。保存、预览模板不会发送消息。发布脚本会补齐 `default_dept_ids`、`include_child_depts`，保留原人员设置。

依赖 api.dingtalk.DingTalkMessageSendApi，传入 DingTalkMessageSendReqDTO：

```java
var request = new DingTalkMessageSendReqDTO();
request.setRequestId("pms-task-assigned-1001-v1");
request.setTemplateCode("pms_task_assigned");
request.setUserIds(List.of(100L));
request.setParams(Map.of("taskName", "检查项目文档", "taskId", "1001"));
request.setBusinessId("task:1001");
var results = dingTalkMessageSendApi.send(request);
```

一次最多 20 个系统用户，重复用户会合并。系统先校验全部收件人及模板参数，再创建发送记录并调用一次批量发送接口。模板和日志均按租户隔离，调用方必须有正确的租户上下文。已有登录绑定的员工在下拉选项、默认人员与部门展开中会被识别为已关联；列表查询只查本地绑定，真正发送时才转换企业 userId。转换失败不会把 UnionID 当作 userId 发送，也不会自动改写用户资料。

当前接入仍是部署级单企业应用，不支持为不同租户动态配置不同企业凭证。

应在业务事务提交成功后调用；发送方法挂起外层事务，日志独立落库，避免真实发送后记录随业务事务回滚。远程微服务拆分时，可保留 DTO 和接口语义，改用可靠事件/消息队列触发发送。

## 结果与重复请求

- 0 处理中：已创建记录，可能尚在调用或更新中；进程异常退出可能留下该状态，不能直接视为失败重新发送。
- 1 钉钉已受理：取得 processQueryKey，且接收人没有出现在无效或限流名单中；不代表员工已读或实际送达。
- 2 发送失败：钉钉明确拒绝、无效接收人、限流，或发起发送前无法取得 token。
- 3 结果未知：网络异常、服务端异常、返回格式异常，存在实际已发送的可能。

同一租户、requestId、系统用户有唯一约束。重复请求返回已有记录，不会自动再次发送；变更消息内容不能复用原 requestId。日志保存渲染后的消息快照，不随模板修改或删除而变化。没有自动重试任务；结果未知必须先核实收件情况，确定要重新发送后使用新的 requestId。日志也是幂等记录，不提供删除入口。

## 验证范围

后端测试覆盖模板渲染、参数/URL/长度校验、部分失败、token 失效、去重及未知状态。PostgreSQL 测试通过显式 -Ddingtalk.pg.test=true 开启，仅面向本机端口 15439 的临时验证库，先执行迁移再运行。正常测试不连接该库。真实钉钉发送与已读不在本地模拟验证范围内。
