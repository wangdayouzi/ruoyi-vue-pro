# PT-P900 试剂标签打印改造实施流程

## 1. 目标与边界

将现有“浏览器预览后手工选择打印机”的试剂标签打印，改为由 Windows 本地打印代理自动调用 Brother PT-P900 打印。用户在页面手动选择多个固定模板之一；不做模板版本控制。

- Linux 上的业务系统负责：用户权限、标签数据、模板版本、打印任务、状态回传和审计。
- 连接 PT-P900 的 Windows 电脑负责：接收任务、调用 Brother 驱动与 b-PAC、实际出纸、上报结果。
- 页面和业务只使用“打印机”概念；不建立或展示“打印站”概念。
- 用户提交任务时必须选择一台已启用的逻辑打印机；系统不接受前端传入任意 Windows 打印机名称。

本次不再使用以下方式作为正式打印链路：

- `window.print()` 后由用户手工选择 PT-P900、纸张、缩放比例；
- 后端生成 A4 Excel 后再由用户打印；
- Linux 服务直接访问 Windows 电脑或 USB 打印机。

## 2. 目标架构

```text
Web 页面
  │ 选择“打印机”、模板、数量，提交标签字段
  ▼
Linux 业务服务
  ├─ 校验权限、模板和打印机状态
  ├─ 创建不可变 print_job
  └─ 提供代理领取任务、回传结果的接口
  ▲                                      │
  │ HTTPS 主动轮询 / 长连接              │
Windows Label Print Agent                │
  ├─ 读取本机 Brother PT-P900 驱动       │
  ├─ b-PAC 打开 .lbx 模板、替换对象内容  │
  ├─ 为每台打印机串行打印                │
  └─ 回传成功、失败、错误详情 ───────────┘
  │
  ▼
PT-P900
```

代理必须主动连接 Linux 服务（HTTPS），不要求 Linux 反向访问 Windows，也不在 Windows 上开放公网入站端口。

## 3. 现状与改造范围

当前页面在 `yudao-ui-admin-vue3-xn/src/views/reagent/label-print/index.vue` 中使用 `window.print()`；后端 `/reagent/label-print/print` 生成的是 Excel 文件。两者都不适合稳定地控制 PT-P900 标签纸。

改造范围：

1. 保留按 BASID 查询试剂及编辑标签字段的现有能力。
2. 移除正式流程中浏览器打印与 Excel 打印按钮的依赖；如有历史需求，可保留为“导出 Excel”，但不再命名为“打印”。
3. 新增模板下拉列表、逻辑打印机、打印任务和打印日志；不实现模板版本、历史或自动发布。
4. 新建独立的 Windows `.NET` 打印代理项目，调用 Brother b-PAC。

## 4. 数据模型

### 4.1 逻辑打印机 `reagent_label_printer`

每一条记录就是用户在页面中选择的一台打印机。

| 字段 | 说明 |
| --- | --- |
| `id` | 主键；打印任务仅引用此字段 |
| `name` | 页面显示名称，例如“上海试剂室 PT-P900-01” |
| `agent_id` | 管理该打印机的 Windows 代理身份 |
| `system_printer_name` | Windows 驱动中的准确打印机队列名称 |
| `model` | 固定为 `PT-P900`（后续可扩展） |
| `tape_width_mm` | 当前允许的纸带宽度，例如 `36` |
| `default_template_id` | 默认标签模板 |
| `enabled` | 是否允许下发新任务 |
| `last_heartbeat_time` | 代理最近一次心跳时间 |
| `online_status` | 在线、离线、故障、纸带不匹配等 |

在线状态以代理服务的成功心跳为准：默认心跳间隔 30 秒，后端在读取打印机列表或创建打印任务时，若 `last_heartbeat_time` 距当前超过 90 秒即判定为离线。它只代表 Windows 代理可连接后端，不代表纸带、模板或实体打印机已通过真机检测。

### 4.2 标签模板 `reagent_label_template`

| 字段 | 说明 |
| --- | --- |
| `id` / `code` | 模板标识，例如 `REAGENT_36MM_V1` |
| `name` | 管理页面显示名称 |
| `version` | 不可变版本号 |
| `file_hash` | `.lbx` 文件校验值 |
| `tape_width_mm` | 适用纸带宽度 |
| `field_schema` | 可替换字段定义、长度限制、是否必填 |
| `enabled` | 是否可用于新任务 |

`.lbx` 由 P-touch Editor 维护。模板中的可变对象必须使用固定名称，例如：`name`、`basId`、`batchNo`、`storageCondition`、`storageLocation`、`receiveDate`、`receiverName`、`expireDate`、`remark`、`barcode`。

### 4.3 打印任务 `reagent_label_print_job`

| 字段 | 说明 |
| --- | --- |
| `id` / `job_no` | 任务身份和用户可见编号 |
| `printer_id` | 用户选择的逻辑打印机 |
| `template_id` / `template_version` | 创建任务时锁定的模板版本 |
| `data_snapshot` | 标签字段完整 JSON 快照 |
| `copies` | 打印份数 |
| `status` | `PENDING`、`CLAIMED`、`PRINTING`、`SUCCESS`、`FAILED`、`CANCELED` |
| `idempotency_key` | 防止用户重复点击产生重复任务 |
| `creator` / `create_time` | 申请打印人和时间 |
| `agent_id` / `claimed_time` | 实际执行代理和领取时间 |
| `printed_count` | 已完成份数 |
| `error_code` / `error_message` | 可诊断的失败原因 |
| `completed_time` | 最终完成时间 |

任务创建后，`data_snapshot` 和模板版本不允许修改。重新打印必须创建新任务，并关联原任务编号，保证审计可追溯。

## 5. Linux 服务端实施

### 阶段 1：数据库与管理接口

1. 新增上述三张核心表和必要索引：`printer_id + status + create_time`、`agent_id + status`、`idempotency_key` 唯一索引。
2. 增加逻辑打印机后台管理页面：创建、禁用、绑定代理、绑定 Windows 打印机队列、选择默认模板、查看在线状态。
3. 增加模板后台管理页面：上传模板包、录入字段定义、启用/停用、创建新版本；已被任务引用的旧版本不得覆盖。
4. 为每台代理创建独立机器凭证；凭证只允许领取其授权打印机的任务、心跳和回传状态。

### 阶段 2：打印任务 API

1. 新增 `POST /reagent/label-print/jobs`：前端提交 `printerId`、`templateId`、`copies` 和标签字段。
2. 服务端校验：用户是否有该打印机权限、打印机是否启用/在线、模板与纸带是否匹配、字段是否完整、数量是否在限制内。
3. 服务端生成任务并返回 `jobNo`、初始状态、排队位置（可选）。
4. 新增 `GET /reagent/label-print/jobs/{id}` 和分页查询接口，供页面查看状态及审计记录。
5. 新增代理接口：领取任务、下载指定模板版本、上报心跳、上报进度、提交成功或失败结果。
6. 对代理领取任务采取“原子领取”策略，避免同一任务被多个代理领取；按 `printer_id` 串行派发任务。

### 阶段 3：前端改造

1. 在试剂标签打印页面增加必填的“打印机”下拉框；默认选中当前用户的默认打印机（若已配置）。
2. 用户修改标签字段后，点击“提交打印”，请求创建任务，而不是调用 `window.print()`。
3. 提交成功后显示任务号和实时状态；可用短轮询或 WebSocket 刷新。
4. 显示明确状态：排队中、代理已领取、正在打印、成功、失败。
5. 失败时展示可理解的错误：代理离线、Windows 找不到打印机、纸带宽度不匹配、模板下载失败、b-PAC 调用失败、打印机脱机等。
6. “重新打印”需要二次确认，并生成新的任务；“取消”仅允许取消尚未领取的任务。

## 6. Windows 打印代理实施

### 6.1 技术选型

使用 C#/.NET 开发独立 Windows 服务（必要时辅以托盘配置工具）。原因是 Brother b-PAC 是 Windows COM 组件，.NET 调用、部署和服务化最稳定。

不将 Brother SDK 或 USB 驱动部署到 Linux。代理运行账户应使用能访问 Brother 打印机驱动的本地服务账户；首次安装和真机调试期间可使用交互式账户验证权限。

### 6.2 Windows 前置安装

每台连接标签机的电脑执行一次：

1. 安装 PT-P900 官方 Windows 驱动，并从 Windows“打印机和扫描仪”打印测试页。
2. 安装 P-touch Editor，用于创建及校准 `.lbx` 标签模板。
3. 安装 b-PAC Runtime（开发机另安装 b-PAC SDK）。
4. 安装 Label Print Agent。
5. 将系统打印机队列名称记录到后台的 `system_printer_name`；不要仅凭显示名称猜测。

### 6.3 代理本地配置

本地只保留代理自身必要配置，不把业务模板规则和可选打印机名单散落在配置文件中。

```json
{
  "serverUrl": "https://example.com/api",
  "agentId": "agent-uuid",
  "agentCredential": "machine-credential",
  "pollIntervalSeconds": 3,
  "templateCacheDirectory": "C:\\ProgramData\\LabelPrintAgent\\templates",
  "logDirectory": "C:\\ProgramData\\LabelPrintAgent\\logs"
}
```

代理启动后执行：

1. 读取 Windows 已安装打印机队列并上报；
2. 上报代理版本、b-PAC 可用状态、模板缓存校验值和每台绑定打印机状态；
3. 领取属于自身管理打印机的任务；
4. 缺少对应模板版本时下载、校验并缓存；
5. 按打印机维度加锁，确保同一 PT-P900 永远串行出纸；
6. 使用 b-PAC 打开模板，按对象名填充字段，选择指定 Windows 打印机，执行打印；
7. 每份完成后更新进度，最终回传成功或结构化错误。

### 6.4 b-PAC 执行原则

1. 模板设计时指定 PT-P900 和纸带规格，避免每次由浏览器或操作人选择纸张。
2. 不使用对象序号，必须使用稳定对象名替换文本、条码和图片。
3. 打印前检查 Windows 打印机在线状态、型号及当前纸带宽度（可识别时）；不匹配直接失败，不强行出纸。
4. b-PAC 的 COM 对象需在受控线程中创建和释放；代理需要捕获 COM 异常、超时和驱动异常。
5. 网络短暂中断时不得盲目重新打印：以任务领取令牌和已回传进度判断，避免产生重复标签。

### 6.5 `.lbx` 模板变量替换规则（当前代理实现）

代理不通过扫描文本内容来寻找全部对象。b-PAC3 COM 无法枚举 `.lbx` 中的所有对象，因此模板必须使用以下两种**对象名称约定**之一。对象名称与对象显示的文字内容是两回事。

#### 方式 A：整张标签使用一个文本对象（推荐）

适用于一整个文本框排版整张标签的模板。

1. 选中这个文本对象，将其**对象名称**设置为 `content-temp`。
2. 在对象的**内容**中按需写变量，例如：

```text
名称：{{name}}
BASID：{{basId}}
批号：{{batchNo}}
储存条件：{{storageCondition}}
存储位置：{{storageLocation}}
收货日期：{{receiveDate}}
接收人：{{receiverName}}
失效日期：{{expireDate}}
备注：{{remark}}
```

3. 代理取得 `content-temp` 对象后，会将该对象内容中的所有已知 `{{变量名}}` 替换为当前打印任务的实际值，再打印。

固定文字（如“名称：”“批号：”）无需变量，保持在上述内容中即可。

`storageLocation`（存储位置）由 SQL Server 的 `sdpm027.pm02726` 自动带入“打印标签信息”，并作为任务快照保存；用户仍可在打印前按需要修改。

#### 方式 B：每个变量使用一个独立文本对象

适用于标题、值、条码等分别排版的模板。固定标题对象可以使用任意名称；每个动态值对象名称必须是“字段名 + `-temp`”。例如：

| 业务字段 | 动态对象名称 | 对象初始内容示例 |
|---|---|---|
| 名称 | `name-temp` | `{{name}}` |
| BASID | `basId-temp` | `{{basId}}` |
| 批号 | `batchNo-temp` | `{{batchNo}}` |
| 储存条件 | `storageCondition-temp` | `{{storageCondition}}` |
| 存储位置 | `storageLocation-temp` | `{{storageLocation}}` |
| 收货日期 | `receiveDate-temp` | `{{receiveDate}}` |
| 接收人 | `receiverName-temp` | `{{receiverName}}` |
| 失效日期 | `expireDate-temp` | `{{expireDate}}` |
| 备注 | `remark-temp` | `{{remark}}` |

例如固定标题对象内容为“名称：”，对象名称可为 `name-title`；右侧显示实际名称的文本对象名称应为 `name-temp`。代理会把后者的整个对象内容设置为当前任务中的名称。

#### 注意事项

- `{{name}}` 写在内容中本身不会触发替换；触发条件是对象名称符合 `content-temp` 或 `字段名-temp`。
- 两种方式可以同时存在：代理先替换 `content-temp` 内的变量，再替换独立字段对象。
- 修改并保存 `.lbx` 到既有路径后，下一条打印任务会自动读取新模板，**不需要重启代理**。
- 修改 `appsettings.json`（模板路径、服务地址、AgentCode 等）才需要重启代理或 Windows 服务。
- 任务一旦成功回传不会因模板修改而重新打印；修改后请新建一条任务验证。

### 6.6 新标签电脑 / 新 PT-P900 的配置步骤

每台新增电脑使用一个唯一的 `AgentCode` 和 `AgentToken`；同一台电脑连接多台 PT-P900 时，这些打印机可以共用同一个 AgentCode，但每台打印机都需要在服务端单独建一条打印机记录。

1. 在新电脑安装 PT-P900 Windows 驱动和 **64 位 b-PAC Runtime**；使用 Windows 打印测试页确认标签带规格、标签长度和裁切均正确。只有设计/维护模板的电脑才需要安装 P-touch Editor 或完整 b-PAC SDK。
2. 将完整代理发布包复制为 `D:\print\win-x64-net8-clean`，将两个模板放到 `D:\print\print-template\reagent-standard.lbx` 和 `D:\print\print-template\sh-reagent-standard.lbx`。代理运行不依赖安装 .NET。
3. 用 Windows PowerShell 获取实际打印机队列名称：

```powershell
Get-Printer | Format-Table Name, DriverName, PortName, PrinterStatus
```

4. 编辑 `D:\print\win-x64-net8-clean\appsettings.json`。`ServerBaseUrl` 必须以 `/admin-api` 结束，路径中的反斜杠必须写成 `\\`：

```json
{
  "LabelPrintAgent": {
    "ServerBaseUrl": "https://cms.accurantbio.com:64234/admin-api",
    "AgentCode": "SH-PTP900-02",
    "AgentToken": "为本电脑单独生成的随机密钥",
    "PollIntervalSeconds": 3,
    "HeartbeatIntervalSeconds": 30,
    "Templates": {
      "REAGENT_STANDARD": "D:\\print\\print-template\\reagent-standard.lbx",
      "SH_REAGENT_STANDARD": "D:\\print\\print-template\\sh-reagent-standard.lbx"
    }
  }
}
```

5. 在 PostgreSQL 的实际业务 schema（当前环境通常为 `mes`）为新打印机新增记录。`agent_token_hash` 填写步骤 4 中 AgentToken 的 SHA-256 小写十六进制值；`system_printer_name` 必须与步骤 3 查到的名称完全一致：

```sql
SET search_path TO mes, public;

INSERT INTO reagent_label_printer
    (id, name, agent_code, agent_token_hash, system_printer_name, model,
     tape_width_mm, template_code, status, online_status, creator, updater)
VALUES
    (nextval('reagent_label_printer_seq'),
     '上海试剂室 PT-P900-02',
     'SH-PTP900-02',
     '<AgentToken 的 SHA-256>',
     '<Windows 实际打印机队列名称>',
     'PT-P900', 36, 'REAGENT_STANDARD', 1, 0, 'admin', 'admin');
```

`reagent_label_template` 中也必须已有 `REAGENT_STANDARD` 记录；同一台电脑使用多个手动选择模板时，在 JSON 的 `Templates` 增加模板代码与 `.lbx` 路径即可。

6. 在该目录双击 `install-service.bat` 并接受管理员授权。脚本会创建/更新 `YudaoLabelPrintAgent` Windows 服务，服务程序和 `appsettings.json` 都直接使用当前发布目录，不复制到 ProgramData。验证：

```cmd
sc qc YudaoLabelPrintAgent
sc query YudaoLabelPrintAgent
```

7. 服务启动后会主动心跳。确认后台中该打印机变为在线，再从芋道选择该打印机和模板提交一条单份测试任务。配置文件本身不会自动创建服务端打印机记录；只有步骤 5 的记录与 AgentCode、密钥哈希匹配后，代理才可领取任务。

## 7. 模板设计与发布流程

1. 在一台已安装 PT-P900 的 Windows 开发机中使用 P-touch Editor 创建 36mm 试剂标签模板。
2. 对每个变量对象命名并登记字段，例如 `name`、`basId`、`batchNo`、`expireDate`。
3. 为长文本定义规则：最大字符数、自动缩小字体或截断策略、是否允许换行。
4. 明确条码类型、编码内容、纠错等级和最小可扫描尺寸；用实际扫码枪验证。
5. 在真机打印样张，确认宽度、可打印区、裁切、中文字体、英文文本、日期和条码。
6. 发布时创建新模板版本并生成文件哈希；新任务使用新版本，历史任务始终使用原版本。
7. 将新模板绑定到满足纸带宽度要求的打印机后，再启用给业务用户。

## 8. 分阶段上线计划

### 第 0 阶段：现场确认

- 统计每台 PT-P900 所在 Windows 电脑、Windows 版本、连接方式、Windows 驱动名、纸带规格和网络可达性。
- 确认每台电脑的访问 Linux 服务方式（内网、VPN、HTTPS 域名）。
- 收集现有标签样张及字段要求，确定是否需要条码或二维码。

### 第 1 阶段：单机 PoC

- 选一台 PT-P900 和一套 36mm 纸带。
- 完成 Brother 驱动、P-touch Editor、b-PAC、代理安装。
- 用固定样例数据打印；随后验证动态字段替换、中文、长文本、条码和多份连续打印。
- 验收“代理离线、打印机断开、纸带不匹配、模板缺失”的错误回传。

### 第 2 阶段：业务闭环

- 上线 Linux 的打印机、模板、任务 API 和管理页。
- 改造试剂标签页面，从浏览器打印切换到任务提交。
- 配置一个试剂标签模板和一台生产打印机。
- 完成权限、审计、幂等、防重复打印和重新打印测试。

### 第 3 阶段：多打印机推广

- 逐台部署 Windows 代理并注册逻辑打印机。
- 为不同地点/纸带规格配置名称、权限、默认模板和默认打印机。
- 使用真实用户账号验证：只能看到有权限的打印机；每台打印机任务不串单。
- 保留原浏览器打印入口一段过渡期（仅管理员可用），稳定后下线。

## 9. 验收清单

- 用户只能选择自己有权限且启用的 PT-P900。
- 任务提交后不再出现浏览器系统打印设置窗口。
- 目标打印机在 10 秒内开始处理任务（网络正常时）。
- 同一打印机的并发任务严格按队列执行，标签内容不混排。
- 连续打印指定份数，数量与任务记录一致。
- 标签上的中文、英文、日期、批号、存储条件和条码均正确；条码可被现场设备扫描。
- 代理、Windows 打印机、b-PAC 或纸带异常时，页面可看到具体失败原因。
- 重试不会无故造成重复标签；所有重新打印都有操作人、时间、原任务关联和原因记录。
- Linux 服务无法直接访问 Windows 代理的入站端口；代理仅通过 HTTPS 主动访问服务端。

## 10. 实施前需要确认的输入

1. 每台打印机的编号、实际位置、连接 Windows 电脑、Windows 驱动名、纸带宽度。
2. 最终标签尺寸和样式，以及条码/二维码是否必需。
3. 每个字段的来源、是否允许编辑、最大长度、超长时的业务规则。
4. 哪些用户/角色能使用哪些打印机，是否需要个人默认打印机。
5. Linux 服务的可访问 HTTPS 地址，以及 Windows 电脑是否可访问该地址。
6. Brother b-PAC SDK/Runtime 的目标版本、Windows 位数和 PT-P900 驱动版本。
